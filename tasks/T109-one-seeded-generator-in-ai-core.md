# T109 — One seeded generator in `ai_core`

Size: M · Prereqs: T91 · Files: `godot/addons/ai_core/`, `godot/test/ai_core/`, `modules/ai_core.json`, `python/gameaikit/`, `spec/vectors/`, `python/tests/`, `godot/addons/ai_adversarial/`, `godot/addons/ai_perception/`, `godot/game/maze/`, `modules/`, `docs/adr/0021-the-board-is-the-examples-kernel.md`, `Makefile`

## Goal

The kit has the same generator three times: Marsaglia's 32-bit xorshift,
seed 1 drawing 270369 first, written out so that Python draws the same
stream as GDScript.

- `ai_adversarial`'s `Xorshift` (T86), Python twin
  `gameaikit.adversarial.xorshift`, vectors in
  `spec/vectors/adversarial/xorshift.json`;
- the maze's `MazeDice` (T97), Python twin `gameaikit.maze.dice`, copied
  "so that the maze stands alone: an example reaching into the
  adversarial-search addon for its dice would be listed as using it" --
  `docs/reviews/104-a-small-pac-man-maze.md` found it "bit for bit
  `Xorshift`, and copying it is the right call" while there was nowhere
  shared to put it;
- `ai_perception`'s `ParticleDraws` (T91), with its own twin -- a third
  copy, for the same reason: an addon may not depend on another addon
  (invariant 2).

`docs/godot/maze.md` named the choice: moving one copy into `ai_core` "is
ADR 0021's to decide". The owner decided on 2026-10-29: one generator in
`ai_core`, as recommended.

## Decisions written down first

- **ADR 0021 is amended, not bent.** It keeps `ai_core` to "what more than
  one technique truly shares", "no logic". The amendment says why a seeded
  generator fits: it decides nothing about any game -- no rule, no domain
  word -- and three techniques already share it, each one copying it only
  because there was no shared place. It is a utility in the sense of
  `GridGraph`: a building block, not a behaviour. The amendment also says
  what does not follow from it: no other utility enters `ai_core` without
  the same argument written down.
- **The same stream, bit for bit.** The one generator draws exactly what
  each copy drew, from the same seeds: every existing vector that reads
  draws -- `spec/vectors/adversarial/`, `spec/vectors/maze/`, T91's
  perception vectors -- is regenerated by its `derive.py` and comes out
  **byte for byte** what is committed. A vector that changes is a failure of this task, not a file to
  commit.
- **The Python twin moves too**, into a package `ai_core`'s manifest owns,
  with its own vectors (seed in, the first draws and `uniform`'s values
  out) and a test in both languages; the three twins import it.
- **Invariant 2 still holds**: `ai_adversarial` and `ai_perception` depend
  on `ai_core` only, and the maze now lists `ai_core` instead of carrying
  its own dice. `check_addon_deps.py` and `make lint-modules` green, the
  manifests' `depends_on` updated to what the code uses.

## Steps

1. Read ADR 0021, the three copies and their twins, and each `derive.py`
   that draws.
2. Amend ADR 0021.
3. The generator and its twin in `ai_core`, its vectors, its tests.
4. Replace each copy, one at a time, regenerating that copy's vectors and
   comparing them with `git diff --exit-code spec/vectors/` after each.
5. Delete the copies and their `.uid`s. Their vector files stay, now
   read through the shared generator: they are the proof that nothing
   moved.
