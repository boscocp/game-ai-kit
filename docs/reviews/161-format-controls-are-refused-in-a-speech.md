# Review: wave/161-format-controls-are-refused-in-a-speech

T139, from T129's review (decision 2): R9 refused the controls and the
line and paragraph separators, but Unicode's format controls (category
Cf) still passed. An override could reverse what the screen shows, and a
zero-width joiner could hide a secret from R11. The PR adds Cf, as
Unicode 16.0 lists it (21 runs, 170 code points), to R9 in `LlmValidator`
and `gameaikit.llm.validator`, each naming the runs by hand. It adds the
same runs to `SPEECH_PATTERN` and `spec/llm/reply.schema.json`, adds
`format_controls.runs` and ten vectors to `spec/vectors/llm/replies.json`,
and widens both sweeps.

A fresh context reviewed PR #115 at head 63ee932. **Verdict: approve, no
blocker: one finding for T140 and five nits.**

## What was reviewed

- The PR title and body, the task file and its decisions.
- Both validators: `FORMAT_CONTROLS`, `FORMAT_CLASS`, R9's test and the
  pattern, against Unicode's own Cf.
- The vectors, the committed schema and both suites' new tests, and how
  the runs are compared across the five places that hold them.
- The docs: the technique page in both languages, `spec/llm/README.md`,
  `spec/vectors/llm/README.md` and the new section of
  `docs/local-llm/server.md`.

## Findings

1. **For T140.** R9's test, `_is_refused_by_r9`, is underscore-private in
   both twins. T140 needs it from `HttpRuntime._error_of`. It should make
   it public, with a doc comment, and keep the Python name in step.
2. **Nit.** The test comparing the runs to Unicode 16.0's Cf is skipped on
   CI, whose Python 3.12 has Unicode 15.0. Say so, or check a weaker
   subset on an older table.
3. **Nit.** The `SPEECH_PATTERN` comment is ragged in both twins (a
   108-character line in `llm_validator.gd`). The GDScript file is 385 of
   its 400 lines, which the task Notes should record.
4. **Nit.** The task Notes say a later Unicode changes "the three lists".
   There are five places, and they should be named.
5. **Nit.** The accepted U+200A and U+202F cases are raw characters in
   `replies.json`. They should be escapes a reader can see.
6. **Nit.** In the technique page's R9/R10 row, in both languages, the
   markup belongs after a semicolon, so it does not read as part of the
   format controls.

## What was done about them

1. Recorded in the task file's Notes as T140's input. Not changed here.
2. The test now always runs. On the version the vector names it checks
   equality, as before. On another table it checks that every Cf there is
   in the runs, and that every code point in the runs is Cf or unassigned
   (Cn) there. The comment says why.
3. Both comments are rewrapped. The line count is in the task Notes.
4. The Notes name the five places.
5. `replies.json` was regenerated by the same script, now escaping every
   space character past ASCII (category Zs) too. U+200A, U+202F and the
   older U+00A0 case are escapes now, and the file decodes to the same
   data.
6. Done in both languages. The pt-BR page's `translation_of` is updated.
