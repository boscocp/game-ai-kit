# Review: wave/92-the-catalogue

T76, as amended on 2026-10-26. The catalogue reads both ways: demo →
techniques and technique → demos. The README and its new pt-BR twin keep a
short summary of the AI techniques and the demos ("pois o foco aqui é a
IA"). Everything is generated by `scripts/catalogue.py` and held by its
`--check`.

A fresh context reviewed PR #31 at head e270758.

**Verdict: merge after the should-fixes.** No blockers.

## What the reviewer found sound

- Rows checked by hand against the code their scenes reach: skirmish,
  demo-behaviour, checkers, fighting, stealth, botmatch and racing3d. Each
  mark was right for the modules, and checkers' `ai_learning` really is
  reached only by its Python.
- Every drift plant was rejected:
  - a demo added and not regenerated;
  - code that newly reaches a technique;
  - a README summary edited by hand;
  - markers missing;
  - a technique with no page;
  - a demo missing from `games.json`.
- Writing refuses while a finding other than staleness stands.
- Exit codes: 0 clean, 1 a finding, 2 unreadable input or wrong usage.
- `lint-catalogue` is a `lint-` target in `check-no-engine`, so
  `check-affected` runs it on every wave whatever the wave touched.
- Putting `README.pt-BR.md` in `check_modules.PROSE` is right: a change to
  it selects only the lints.

## Findings

1. **The catalogue ignored the menu's cards, and the README lost the
   algorithms** (should-fix, the most important; the owner's point is the
   AI).
   - `godot/menu/catalogue.json` already lists each demo's techniques at
     the level of algorithms, and `check_demos.py` holds them on stricter
     evidence: a class constructed, called or extended.
   - The two disagreed. The 3D racer's card lists pure pursuit and a speed
     profile (`RaceDriver3D`), but its catalogue row showed only
     `ai_steering`, and `racing_driver` named only `demo-racing`.
     Tic-tac-toe's card lists perfect play by minimax (`TicTacToeSolver`),
     but its row showed only MENACE.
   - The old README table named the algorithms: minimax and alpha-beta,
     A\*, BFS, DFS, Dijkstra, STRIPS, the state machine, the behaviour
     tree, GOAP, HTN, regression, n-gram, seek, arrive, pursue, avoid and
     pure pursuit. The generated summary showed module ids with a few
     words, and A\*, GOAP and minimax appeared in neither README.
2. **C6 was vacuous for MENACE** (should-fix). Its `lives_in` was the
   folder `godot/game/tictactoe/`. The walk counted the scene itself as
   visited, and the scene is inside that folder, so the check always
   passed.
3. **Mutants survived** (should-fix, invariant 4). Each of these could be
   broken without the self-test failing:
   - the folder branch of `reaches()`, which on the real repository gives
     a false C6 for `demo-tictactoe`;
   - the folder branch of `named_by`;
   - the test exclusion, because the fixture's test file could never be
     reached;
   - the level test in `section()` of `check_translations_docs.py`, because
     no planted part had a sub-heading with code under it.
4. **The keys in `games.json` duplicated the `##` help** (should-fix), and
   nothing held the two together.
5. **Nits:**
   - The matrix headers mixed module ids with human titles.
   - The docstrings of `table_row` and `command` did not say why.
   - pt-BR wording: "um boneco que aprende você", the "como" column
     header, "espaço joga a jogada", and "reservas" for claims.
   - The glossary lacked GPU, VRAM, PDDL, OpenGL and Compatibility.
   - The reach analysis's limits were not written down.

## What was done

1. **Algorithms come from the cards.**
   - The catalogue now reads `godot/menu/catalogue.json`. Each algorithm on
     a demo's card is filed under the column whose code holds the evidence
     class the scene reaches: a non-module technique's files first, then a
     technique module. When that class is the example's own, the algorithm
     goes under "written inside the example itself".
   - Tic-tac-toe's perfect play by minimax, the 3D racer's measured grip,
     the RTS's priority queue and the tactical game's rules are now
     surfaced that way.
   - The algorithm names appear in each demo's line, in each technique's
     line (per demo), in the README's technique table (a new "algorithms"
     column) and in its demo table, in both languages.
   - `games.json` gives each card algorithm a short name in English and
     pt-BR. Proper names such as A\*, GOAP and Dijkstra stay as they are.
     New rule C7: an algorithm on a card with no name, or a name for an
     algorithm no card lists.
   - `racing_driver` now lists `demo-racing3d`, with `race_driver_3d.gd`
     and `racing_track.gd` in its `lives_in`. `learned_evaluation` gained
     `checkers_weights.gd` and `behaviour_cloning` gained
     `cloned_player.gd`, so their algorithms file under their own columns.
   - **The reach rule is now `check_demos.py`'s, reused**
     (`project_classes`, `references_of`), not the capitalised-word rule
     from `check_modules.py`. One rule for "this scene uses that class"
     across the kit: the menu's cards are already held to it, and a
     catalogue that counted a type annotation as a use would disagree with
     the cards about the same scene. The walk still follows each file to
     know which example a technique was reached through. Its limits are
     written in the docstring and in "How the marks are measured": a path
     built at run time is invisible, and a branch never taken still
     counts.
2. **C6 now counts scripts only.** The scene file is no longer part of what
   the scene reaches, and MENACE's `lives_in` names `menace_player.gd`.
   Planted case: a non-module technique "living" in the scene file is C6.
3. **A planted case for every survivor:**
   - The fixture's non-module technique lives in a folder, which is the
     `reaches()` folder branch.
   - `named_by`'s folder branch is gone with the rule change, since
     `check_demos.py` follows only paths to a `.gd` or `.tscn`.
   - The fixture's scene now uses a class declared in a test file, so
     `ai_c` stays hollow only while tests are left out.
   - `ai_c` is also named in a type annotation, which is not a use.
   - An algorithm whose evidence is both in a technique and in the
     example's own code belongs to the technique.
   - In `check_translations_docs.py`: code under a sub-heading of a
     mirrored part that differs is D16.

   Mutation round, every mutant caught:
   - 31 on `catalogue.py`, including three on the rule it borrows from
     `check_demos.py`: tests left out, type annotations, comments;
   - 9 on the new code in `check_translations_docs.py`, including the level
     test.
4. **C8 holds the keys to the help line.** The key each `;` clause of
   `keys.en` opens with must be named in its target's `##` help line. It
   found two real drifts on its first run:
   - checkers' E was not in `make help`, so the help line gained it;
   - a skirmish clause opened on "each", so it was reworded.

   The tactical clause was reworded so that it opens on its key.
5. **Nits done:**
   - The matrix headers are all page ids.
   - `table_row` escapes a `|` in a cell, and says why.
   - `command` says why it is never the bare target.
   - pt-BR: "que aprende o seu jeito de jogar", "parecido com", "espaço faz
     a jogada", "a marcação de posições".
   - The glossary gained BFS/DFS, PDDL, GPU/VRAM, OpenGL/Compatibility and
     *script*.
   - No algorithm name has a comma, so a list of names reads as one.
