## Demo by demo {#by-demo}

- <a id="run"></a>**Checkers**, `make run` -- like checkers, you against the computer.
  - keys: space plays white's move; 1-6 how far it looks; E swaps its evaluation for the learned one.
  - techniques: ● [ai_adversarial](ai_adversarial.md) (minimax with alpha-beta); ○ [ai_learning](ai_learning.md) (declared in its manifest, never reached from its scene); ● [Learned evaluation](learned_evaluation.md) (a learned evaluation).
- <a id="demo-skirmish"></a>**The skirmish**, `make demo-skirmish` -- like a small Advance Wars battle.
  - keys: space ends your turn, and each blue unit then says what it decided, and the probability it decided on.
  - techniques: ◐ [ai_learning](ai_learning.md) (through `tactical`; a regression trained in Python); ● [ai_search](ai_search.md) (A*).
- <a id="demo-tictactoe"></a>**Noughts and crosses**, `make demo-tictactoe` -- like tic-tac-toe, against Michie's matchbox machine.
  - keys: space draws MENACE's bead; 1-4 its age; M what perfect play makes of each square.
  - techniques: ● [MENACE](menace.md) (MENACE's matchboxes).
  - written inside the example itself: perfect play by minimax.
- <a id="demo-search"></a>**Four searches**, `make demo-search` -- like the click-to-move of any strategy game, slowed down to one cell at a time.
  - keys: 1-4 choose the search; space reveals the next cell it expanded; B the next board.
  - techniques: ● [ai_search](ai_search.md) (BFS, DFS, Dijkstra, A*).
- <a id="demo-stealth"></a>**Stealth**, `make demo-stealth` -- like the top-down stealth of the first Metal Gear.
  - keys: space waits, and each guard's cone and suspicion move on; D shows the danger map.
  - techniques: ● [ai_fuzzy](ai_fuzzy.md) (fuzzy logic); ● [ai_perception](ai_perception.md) (vision cone with line of sight and hearing, influence map); ● [ai_search](ai_search.md) (A*).
- <a id="demo-steering"></a>**Steering**, `make demo-steering` -- like the enemies of an action game chasing and stopping, one force at a time.
  - keys: click moves a target; space pauses; . one step.
  - techniques: ● [ai_steering](ai_steering.md) (seek, arrive, pursue, avoid).
- <a id="demo-racing"></a>**Racing**, `make demo-racing` -- like Micro Machines, seen from above, the AI in the same car as yours.
  - keys: 1-3 the AI's level; Tab watches the three AIs race.
  - techniques: ● [ai_steering](ai_steering.md) (seek); ● [The racing driver](racing_driver.md) (pure pursuit, speed profile).
- <a id="demo-racing3d"></a>**Racing in 3D**, `make demo-racing3d` -- like Gran Turismo, on tyres that slip.
  - keys: 1 PID, 2 heat line, 3 measured grip -- each on or off; Tab watches the next car.
  - techniques: ● [ai_steering](ai_steering.md) (PID controller, heat line); ● [The racing driver](racing_driver.md) (speed profile, pure pursuit).
  - written inside the example itself: measured grip.
- <a id="demo-infiltration"></a>**Infiltration**, `make demo-infiltration` -- like Metal Gear Solid, in third person.
  - keys: 1-6 switch each part of the guards' reasoning and the director; Tab follows the next guard.
  - techniques: ● [ai_constraints](ai_constraints.md) (constraint satisfaction, AC-3 and backtracking); ● [ai_fuzzy](ai_fuzzy.md) (fuzzy logic); ● [ai_perception](ai_perception.md) (vision shape with light and hearing, awareness, belief map); ● [ai_search](ai_search.md) (A*); ● [ai_teamwork](ai_teamwork.md) (a shared search, role arbiter); ● [ai_utility](ai_utility.md) (utility-weighed actions).
  - written inside the example itself: a director pacing the threats by intensity.
- <a id="demo-botmatch"></a>**Bot match**, `make demo-botmatch` -- like a bot match in Unreal Tournament or Counter-Strike.
  - keys: 1-3 blue's claims, commander and retreat; Tab a bot; T take it over; M the map.
  - techniques: ● [ai_perception](ai_perception.md); ● [ai_search](ai_search.md) (A*); ● [ai_teamwork](ai_teamwork.md) (tactical positions with claims, team commander over influence, squad confidence and retreat in waves); ● [ai_utility](ai_utility.md) (utility-weighed actions).
- <a id="demo-behaviour"></a>**One guard, four ways to decide**, `make demo-behaviour` -- like a guard on its rounds, as in Metal Gear or Thief.
  - keys: 1-4 swap the state machine, the behaviour tree, GOAP and HTN mid-round; space a turn.
  - techniques: ● [ai_behaviour](ai_behaviour.md) (state machine, behaviour tree, GOAP, HTN); ◐ [ai_fuzzy](ai_fuzzy.md) (through `stealth`); ● [ai_perception](ai_perception.md); ● [ai_search](ai_search.md).
- <a id="demo-rts"></a>**Real-time strategy**, `make demo-rts` -- like StarCraft or Age of Empires, against a commander that plans.
  - keys: V watches two computers; H the planner; I the influence map; F lifts the fog.
  - techniques: ● [ai_behaviour](ai_behaviour.md) (HTN, state machine); ● [ai_planning](ai_planning.md) (STRIPS over PDDL); ● [ai_rts_core](ai_rts_core.md) (flow fields).
  - written inside the example itself: priority queue of wishes, utility over regions, influence map.
- <a id="demo-tactical"></a>**Tactics**, `make demo-tactical` -- like Advance Wars, or XCOM.
  - keys: C changes the computer, whose next decision is drawn in pink before space plays it; S swaps sides; in XCOM, N a new map and B its build, a cell at a time.
  - techniques: ● [ai_adversarial](ai_adversarial.md) (Monte Carlo tree search, expectiminimax with a hand-written evaluation); ● [ai_behaviour](ai_behaviour.md) (state machine, behaviour tree, GOAP, HTN); ● [ai_constraints](ai_constraints.md) (wave function collapse); ● [ai_learning](ai_learning.md) (a regression trained in Python); ● [ai_planning](ai_planning.md) (STRIPS over PDDL); ● [ai_utility](ai_utility.md) (utility-weighed actions).
  - written inside the example itself: hand-written rules, lookahead with exact odds, influence map.
- <a id="demo-maze"></a>**Pac-Man, a small maze**, `make demo-maze` -- like Pac-Man, you against Blinky.
  - keys: V the ghosts' view: each ghost's target and the distance from each way; G brings Pinky in; C hands Pac-Man to the MDP: each cell's value, each move's worth.
  - techniques: none.
  - written inside the example itself: a target tile and the shortest straight line, value iteration, an MDP's policy.
- <a id="demo-talk"></a>**Talk your way past the guard**, `make demo-talk` -- like Suck Up!, talking your way in.
  - keys: V the reasoning: the act the model read, the rule that fired, trust and suspicion; Tab types to a live local model.
  - techniques: ● [ai_llm](ai_llm.md) (a language model reading discourse acts, behind a validator).
- <a id="demo-fighting"></a>**Fighting, training mode**, `make demo-fighting` -- like Street Fighter's training mode, against a dummy that learns how you play.
  - keys: M cycles the dummy's mode; space one frame; P pause.
  - techniques: ● [ai_bandit](ai_bandit.md) (a bandit, UCB1); ● [ai_learning](ai_learning.md) (the ghost's case lookup); ● [ai_opponent](ai_opponent.md) (n-gram); ● [Behaviour cloning](behaviour_cloning.md) (behaviour cloning).
  - written inside the example itself: hand-written rules, reaction delay.

## How the marks are measured {#how}

A mark is measured, not written. The catalogue starts from the techniques a demo's manifest declares (`depends_on` in `modules/<example>.json`, directly or through another example it uses), and follows the code from the scene its `make` target opens, file by file, with the rule `check_demos.py` holds the menu's cards to: a class counts when the code constructs it, calls it or extends it, and a `res://` path when it names a script or a scene. Comments, strings, type annotations and constant reads do not count, and tests are left out:

- ● the demo's own code reaches the technique;
- ◐ only another example's code reaches it, and the line names which;
- ○ the demo's manifest declares it and nothing its scene reaches uses it: the dependency belongs to code the demo does not run -- the Python that trains it, or a file the scene never loads.

The algorithms come from the demo's card in the menu (`godot/menu/catalogue.json`): each is filed under the technique whose code holds the class its card names as evidence, or under *written inside the example itself* when that class is the example's own.

What a reading cannot see: a script loaded from a path built at run time, and whether a branch that uses a class is ever taken. Opening the demo is the check for both.

A technique that lives in Python and a demo rather than in an addon (`non_module_techniques.json`) is marked ● on the demos that file names, and `make lint-catalogue` fails when such a demo's scene never reaches one of the technique's Godot scripts. The known game, the keys and the algorithms' short names come from `games.json`, the one hand-written input, and the keys are held to each target's `make help` line.
