# 0012 — Art is CC0 now and generated later, and binary art is committed

Status: accepted · 2026-10-14 (decided in T9)

## Context

Until T9, everything on screen was a flat colour made in code. `board_view.gd`
said why: a reader sees exactly what a tile is without opening the editor, and
"this repository stays free of binary art nobody can diff". That was right
while the board had three kinds of ground and units differed only by side.

It stopped being right when the tactical game (T10, T30) gave the board five
kinds of unit, two towers and a workshop. Five circles in one colour with two
letters on each could not be told apart at a glance, and the owner, playing
the examples, could not tell what several of them were. Colour is not an
answer either: a colour-blind reader is a reader, and five colours are five
chances to fail one.

Two ways to get pictures were on the table: **CC0 art from a pack**, now, or
**art generated by a local model**, which is what the owner wants in the end.

## Decision

**Commit CC0 pictures, and reverse the "no binary art" rule for them.** The
pictures come from four packs by Kenney, all CC0 1.0, listed file by file in
`godot/assets/LICENCES.md`:

- Tiny Battle for the tactical game and the shared board: ground, five
  silhouettes for the five kinds that walk (a truck, a rifleman, a gun, a
  boat, a tank), three buildings for the three that stand, and a red and a
  blue copy of each;
- Boardgame Pack and Board Game Icons for checkers: a red chip, a white
  chip, and a crown, so a king is a man with a crown on it;
- Game Icons and Board Game Icons for noughts and crosses: an X and an O.

What keeps the readability the old rule protected:

- **Each file is the pack's own, byte for byte**, renamed for its role. A
  picture with see-through parts is laid over open ground in code when the
  board is built, rather than a composite being committed. So there is
  nothing in `godot/assets/` that a script here produced and a reader would
  need to re-derive.
- **One table names every picture.** `godot/game/art.gd` is the only code
  that knows a path. The board's atlas is still built in code -- stitched from
  the files rather than filled with colours -- so a reader still sees what a
  tile is without opening the editor.
- **Only what is drawn is committed.** Thirty files, 88 KB.

**Generated art is deferred, not rejected.** T31 is the pipeline: a local
model, downloaded separately and fenced off from every lesson, writing a
person's own pictures to the same paths, gitignored. That is why the paths are
a contract (one file per role, stable names), why `check_license.py` lists
files and not folders, and why it reads `git ls-files`: a generated file is
not committed, so it has nothing to attribute and the gate never sees it.
This task buys the visuals with hours; the generator would have cost weeks of
fighting a diffusion model, and those are weeks not spent on the AI the
repository exists to teach.

## The tier argument

Invariant 5 says no lesson needs hardware above tier 1. Generated art could
look like it breaks that, and it does not, for the same reason invariant 6
holds: **art is a development-time input**. Python trains and GDScript only
infers; in the same way, whoever makes a picture may need a GPU, and the
reader gets the committed PNG and needs nothing. No lesson depends on how a
picture was made, and every example runs on the committed CC0 set.

## Consequences

- **Binary files are in the history.** A changed picture shows as a changed
  blob, not a diff. That is the cost the old rule avoided, accepted because
  each file is small, unedited, and attributed by path.
- **A fresh checkout must import before it can draw.** Measured on 4.7.2: a
  project with no `.godot/` folder answers `load()` of a PNG with "No loader
  found"; only the editor imports, and `--import` is the editor doing it
  headless. `make import` runs it, every target that opens a scene depends on
  it, and so CI imports too. See
  [importing-art.md](../godot/importing-art.md).
- **The `.import` sidecars are committed** for `godot/assets/` only, as
  Godot's documentation says to: they hold the import settings and the uid.
  The rest of the tree still ignores them.
- **The tile palette's brightness argument is gone with the palette.** T8
  chose colours that differ in brightness as well as hue. The pictures differ
  in shape -- trees, a rock, water, a road, a flag -- and the manual check is
  where a person confirms that is enough.
